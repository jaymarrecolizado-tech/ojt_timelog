1. PROJECT OVERVIEW
1.1 Project Title
OJT Time Log Management System (OJT-TLMS)

1.2 Project Description
A web-based time log management system designed to track and manage the attendance of On-the-Job Training (OJT) students. The system uses a TOTP-style rotating QR code displayed on a guard's device, which students scan using their personal mobile phones to record their time-in and time-out. The system automatically computes rendered hours and generates a properly formatted Daily Time Record (DTR) report.

1.3 Problem Statement
text

Current Pain Points:
├── Manual paper-based DTRs are prone to falsification
├── Students can claim hours they didn't actually render
├── No real-time visibility of who is present on-site
├── Compiling attendance data at end of OJT is tedious
├── Paper DTRs get lost, damaged, or are illegible
├── Coordinators have no way to monitor remotely
└── No centralized record — each student keeps their own copy
1.4 Proposed Solution
text

Solution Components:
├── Rotating QR code (changes every 30 seconds) on guard's device
├── Mobile-friendly web app for students to scan QR
├── Automated time-in/time-out logging with timestamps
├── Real-time dashboard for administrators
├── Automated DTR generation in PDF format
└── Accumulated hours tracking against required OJT hours
2. OBJECTIVES & GOALS
2.1 General Objective
To develop a web-based OJT Time Log Management System that automates attendance tracking through QR code scanning and generates formatted Daily Time Records.

2.2 Specific Objectives
text

ID    Objective                                              Priority
─────────────────────────────────────────────────────────────────────
OBJ-1 Implement a TOTP-based rotating QR code system         HIGH
      that changes every 30 seconds to prevent fraud

OBJ-2 Enable students to clock in/out by scanning QR         HIGH
      codes using their mobile phone camera

OBJ-3 Automatically determine whether a scan is a            HIGH
      TIME IN or TIME OUT based on sequence logic

OBJ-4 Store all time log entries in a centralized database   HIGH

OBJ-5 Calculate total hours rendered per day, per month,     HIGH
      and accumulated total

OBJ-6 Generate DTR reports in the prescribed format          HIGH
      (Date, AM In/Out, PM In/Out, Hours Rendered)

OBJ-7 Allow students to view their own logs and              MEDIUM
      download their DTR as PDF

OBJ-8 Provide an admin dashboard with real-time attendance   MEDIUM
      overview, absentee tracking, and report generation

OBJ-9 Support admin overrides for missed/incorrect entries   MEDIUM
      with a full audit trail

OBJ-10 Implement geolocation verification as an optional     LOW
       layer of attendance validation

3. SCOPE & LIMITATIONS
3.1 In Scope
text

✅ User registration and authentication (students, guards, admins)
✅ TOTP-style rotating QR code display (guard device)
✅ QR code scanning via phone camera (student device)
✅ Automatic time-in/time-out logging
✅ Smart IN/OUT sequence detection (AM IN → AM OUT → PM IN → PM OUT)
✅ Daily, monthly, and cumulative hours calculation
✅ DTR report generation (PDF format)
✅ Student dashboard (personal logs, hours summary)
✅ Admin dashboard (live attendance, absentees, reports)
✅ Manual entry override by admin (with audit trail)
✅ Weekend and holiday detection
✅ PWA (Progressive Web App) for mobile installation
✅ Export to PDF and CSV/Excel
3.2 Out of Scope (V1)
text

❌ Native mobile app (iOS/Android) — using PWA instead
❌ Biometric or facial recognition verification
❌ NFC-based scanning
❌ Payroll integration
❌ SMS notifications
❌ Multi-company/multi-site deployment (single site only in V1)
❌ Offline mode with sync
❌ Integration with school LMS or student portal
3.3 Constraints
text

├── Students must have a smartphone with a camera
├── Students must have internet access at the OJT site
├── Guard must have a device (phone/tablet) with internet
├── System depends on Supabase free tier limits (500MB DB, 50K requests)
└── QR scanning requires HTTPS (camera access requirement)
3.4 Assumptions
text

├── OJT schedule follows a standard AM/PM split (e.g., 8-12, 1-5)
├── There is one entry/exit point where the guard is stationed
├── Each student has only one active OJT assignment at a time
├── The guard's device remains powered and connected during OJT hours
└── Students will use their personal smartphones

5.3.2 DTR Generation Flow
text

Student selects month/year
       │
       ▼
GET /api/reports/dtr?student_id=X&month=2&year=2024
       │
       ▼
┌──────────────────────────────────────┐
│        DTR BUILDER                    │
│                                       │
│ 1. Get all days in Feb 2024 (1-29)   │
│ 2. Query time_logs for student       │
│    WHERE month = 2 AND year = 2024   │
│ 3. Group logs by date                │
│ 4. For each day:                     │
│    ├── Weekend? → Mark SATURDAY/SUN  │
│    ├── Holiday? → Mark HOLIDAY       │
│    ├── No logs? → Mark ABSENT        │
│    └── Has logs? → Pair as:          │
│        Scan 1 = AM IN               │
│        Scan 2 = AM OUT              │
│        Scan 3 = PM IN               │
│        Scan 4 = PM OUT              │
│ 5. Calculate hours per day           │
│ 6. Sum total monthly hours           │
│ 7. Get accumulated hours to date     │
│ 8. Calculate remaining hours         │

9.2 Complete Table Definitions
SQL

-- ============================================
-- TABLE: users (extends Supabase auth.users)
-- ============================================
CREATE TABLE public.profiles (
    id              UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
    email           VARCHAR(255) NOT NULL UNIQUE,
    role            VARCHAR(20) NOT NULL DEFAULT 'student'
                    CHECK (role IN ('student', 'guard', 'admin', 'super_admin')),
    is_active       BOOLEAN NOT NULL DEFAULT true,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- ============================================
-- TABLE: students
-- ============================================
CREATE TABLE public.students (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         UUID NOT NULL UNIQUE REFERENCES public.profiles(id) ON DELETE CASCADE,
    student_id_no   VARCHAR(20) NOT NULL UNIQUE,
    first_name      VARCHAR(100) NOT NULL,
    middle_name     VARCHAR(100),
    last_name       VARCHAR(100) NOT NULL,
    suffix          VARCHAR(10),                    -- Jr., III, etc.
    department      VARCHAR(150) NOT NULL,
    program         VARCHAR(150) NOT NULL,
    company         VARCHAR(200),
    company_address VARCHAR(300),
    supervisor_name VARCHAR(200),
    ojt_start       DATE,
    ojt_end         DATE,
    required_hours  DECIMAL(7,2) NOT NULL DEFAULT 500.00,
    contact_no      VARCHAR(20),
    status          VARCHAR(20) NOT NULL DEFAULT 'active'
                    CHECK (status IN ('pending', 'active', 'completed', 'inactive')),
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_students_user_id ON students(user_id);
CREATE INDEX idx_students_status ON students(status);
CREATE INDEX idx_students_department ON students(department);

-- ============================================
-- TABLE: time_logs
-- ============================================
CREATE TABLE public.time_logs (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    student_id      UUID NOT NULL REFERENCES public.students(id) ON DELETE CASCADE,
    log_type        VARCHAR(3) NOT NULL CHECK (log_type IN ('IN', 'OUT')),
    log_category    VARCHAR(2) NOT NULL CHECK (log_category IN ('AM', 'PM')),
    timestamp       TIMESTAMPTZ NOT NULL,
    date            DATE NOT NULL,                  -- extracted date for easy querying
    qr_token_hash   VARCHAR(64),                    -- SHA256 of the QR token scanned
    location_id     UUID REFERENCES public.locations(id),
    latitude        DECIMAL(10, 8),
    longitude       DECIMAL(11, 8),
    device_info     VARCHAR(500),
    ip_address      INET,
    is_manual       BOOLEAN NOT NULL DEFAULT false, -- true if admin-entered
    is_flagged      BOOLEAN NOT NULL DEFAULT false,
    flag_reason     VARCHAR(200),
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_time_logs_student_date ON time_logs(student_id, date);
CREATE INDEX idx_time_logs_date ON time_logs(date);
CREATE INDEX idx_time_logs_timestamp ON time_logs(timestamp);
CREATE INDEX idx_time_logs_student_id ON time_logs(student_id);

-- Prevent duplicate scans (same student, same type, same category, same date)
CREATE UNIQUE INDEX idx_unique_log_entry
    ON time_logs(student_id, date, log_type, log_category);

-- ============================================
-- TABLE: log_overrides (audit trail)
-- ============================================
CREATE TABLE public.log_overrides (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    time_log_id     UUID REFERENCES public.time_logs(id) ON DELETE SET NULL,
    student_id      UUID NOT NULL REFERENCES public.students(id),
    admin_id        UUID NOT NULL REFERENCES public.profiles(id),
    action          VARCHAR(20) NOT NULL
                    CHECK (action IN ('CREATE', 'UPDATE', 'DELETE')),
    old_values      JSONB,
    new_values      JSONB,
    reason          TEXT NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_overrides_student ON log_overrides(student_id);
CREATE INDEX idx_overrides_admin ON log_overrides(admin_id);

-- ============================================
-- TABLE: locations (QR stations/gates)
-- ============================================
CREATE TABLE public.locations (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name            VARCHAR(100) NOT NULL,
    description     VARCHAR(300),
    latitude        DECIMAL(10, 8),
    longitude       DECIMAL(11, 8),
    radius_meters   INTEGER DEFAULT 100,            -- geofence radius
    is_active       BOOLEAN NOT NULL DEFAULT true,
    secret_key      VARCHAR(128) NOT NULL,          -- HMAC secret for this location
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- ============================================
-- TABLE: holidays
-- ============================================
CREATE TABLE public.holidays (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    date            DATE NOT NULL,
    name            VARCHAR(200) NOT NULL,
    type            VARCHAR(20) DEFAULT 'regular'
                    CHECK (type IN ('regular', 'special', 'company')),
    is_recurring    BOOLEAN NOT NULL DEFAULT false,  -- same date every year

    ON time_logs FOR SELECT
    USING (student_id IN (

    ON profiles FOR SELECT

        )
    );

9.3 Database Views
SQL

-- ============================================
-- VIEW: daily_summary (pre-computed daily view)
-- ============================================
CREATE OR REPLACE VIEW daily_summary AS
SELECT
    s.id AS student_id,
    s.student_id_no,
    s.first_name,
    s.last_name,
    s.department,
    tl.date,
    MAX(CASE WHEN tl.log_category = 'AM' AND tl.log_type = 'IN'
        THEN tl.timestamp END) AS am_in,
    MAX(CASE WHEN tl.log_category = 'AM' AND tl.log_type = 'OUT'
        THEN tl.timestamp END) AS am_out,
    MAX(CASE WHEN tl.log_category = 'PM' AND tl.log_type = 'IN'
        THEN tl.timestamp END) AS pm_in,
    MAX(CASE WHEN tl.log_category = 'PM' AND tl.log_type = 'OUT'
        THEN tl.timestamp END) AS pm_out,
    -- Calculate hours
    COALESCE(
        EXTRACT(EPOCH FROM (
            MAX(CASE WHEN tl.log_category = 'AM' AND tl.log_type = 'OUT'
                THEN tl.timestamp END) -
            MAX(CASE WHEN tl.log_category = 'AM' AND tl.log_type = 'IN'
                THEN tl.timestamp END)
        )) / 3600.0, 0
    ) +
    COALESCE(
        EXTRACT(EPOCH FROM (
            MAX(CASE WHEN tl.log_category = 'PM' AND tl.log_type = 'OUT'
                THEN tl.timestamp END) -
            MAX(CASE WHEN tl.log_category = 'PM' AND tl.log_type = 'IN'
                THEN tl.timestamp END)
        )) / 3600.0, 0
    ) AS total_hours,
    -- Check completeness
    COUNT(*) AS scan_count,
    CASE
        WHEN COUNT(*) = 4 THEN 'COMPLETE'
        WHEN COUNT(*) > 0 THEN 'INCOMPLETE'
        ELSE 'ABSENT'
    END AS status
FROM students s
LEFT JOIN time_logs tl ON s.id = tl.student_id
GROUP BY s.id, s.student_id_no, s.first_name, s.last_name,
         s.department, tl.date;

-- ============================================
-- VIEW: accumulated_hours
-- ============================================
CREATE OR REPLACE VIEW accumulated_hours AS
SELECT
    s.id AS student_id,
    s.student_id_no,
    s.first_name || ' ' || s.last_name AS full_name,
    s.department,
    s.required_hours,
    COALESCE(SUM(ds.total_hours), 0) AS total_accumulated,
    s.required_hours - COALESCE(SUM(ds.total_hours), 0) AS remaining_hours,
    ROUND(
        (COALESCE(SUM(ds.total_hours), 0) / s.required_hours) * 100, 1
    ) AS completion_percentage
FROM students s
LEFT JOIN daily_summary ds ON s.id = ds.student_id
GROUP BY s.id, s.student_id_no, s.first_name, s.last_name,
         s.department, s.required_hours;
